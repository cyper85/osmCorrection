Help

osmCorrection finds faulty values in OpenStreetMap, such as phone numbers in the wrong format, broken websites or duplicate tags, and suggests a correction. You look at each finding, decide yourself, and upload the changes with your OSM account at the end. Everything runs in your browser.

Log in or just look around

  • Log in with OpenStreetMap: You are sent to openstreetmap.org and allow osmCorrection to upload changes and notes in your name. osmCorrection never sees your password.
  • Look around without logging in: You can try everything and work on findings. To upload, you log in later; your changes are kept.

1. Choose data

  1. Search for a place or move the map until the frame shows the area you want. It is at most 500 m × 500 m. If the map is zoomed out too far, loading is disabled.
  2. Tick what should be checked (see below). The browser remembers your choice.
  3. Click Download and check. The data comes from an Overpass server, which usually takes a few seconds.

The checks

  • Phone and fax numbers, e-mail addresses, websites, Wikipedia, Wikidata: the format of the values, e.g. 0049 … instead of +49 …, a missing https://, spaces in e-mail addresses.
  • Social networks: links to profiles, chosen as a group or one by one (“choose individually”).
  • Duplicate values: the same value in website and contact:website or similar pairs.

The online checks also contact services or websites:

  • Check Wikidata references online: Does the Wikidata item still exist, and does the wikipedia tag match it?
  • Check websites online: Your browser opens every website in the frame and reports whether it answers and whether it is also available via https.
  • Confirm websites and profiles: Also shows valid links that have not been checked for a long time. You open and confirm them, see Confirming.
  • Compare with AI: see AI assistance.

2. Review

The findings come one after the other. For each you see the object (link to openstreetmap.org), the tag, the current value and the finding.

  1. Check the new value. Usually a correction is already filled in; you can change it. Below it you see right away whether the value is valid.
  2. Apply keeps the change for later. Nothing is uploaded before step 3.
  3. Skip leaves the value as it is. Back goes to the previous finding.
  4. Delete tag removes the tag completely, e.g. a website that no longer exists.

No longer exists …

For shops or places that have closed. For each tag you decide whether it stays, is deleted or gets a prefix:

  • disused: for empty shops, was: for anything that is gone completely.
  • Below you see which tags remain. A node without tags is deleted on upload if it is not part of a way or relation.

Check on site …

When something can only be settled on site: osmCorrection creates an OSM note at the object. Mappers nearby see it on the map and in StreetComplete. The text is prepared and can be changed. You need to be logged in for this.

Confirming websites and profiles

With the online check “Confirm websites and profiles” you also get valid links that have not been checked for a long time:

  1. Open in a new tab and look: Does the page still exist, and does it belong to this object?
  2. Opened and checked (Ctrl+Enter) sets check_date:<tag> to today. The button is enabled only after opening.
  3. If something is wrong, correct the value, delete the tag or choose “No longer exists …”.

3. Upload

  1. Continue to upload shows all kept changes, the old value struck through, the new one in green. remove takes a change out again.
  2. Check the changeset comment. It is made from the changes and can be edited.
  3. Upload. All changes go into one changeset; its link appears afterwards.

Before uploading, osmCorrection checks whether someone has changed the objects in the meantime. Such conflicts are shown and skipped; nothing is overwritten. Until the upload, the changes stay saved in your browser, even if you close the page.

AI assistance

An AI reads the website of an object and suggests changed or missing opening hours, phone, mobile, fax, e-mail, WhatsApp and social media profiles. It also reports signs that a shop has closed, has moved, or that the domain is no longer used.

  • Every suggestion has a literal quote and a link to the source page. If the quote is not on the page, the suggestion is rejected.
  • The AI only makes suggestions: you check and apply each one.
  • Only the website from the OSM tag is fetched, never Facebook, Instagram, Google or other closed networks.
  • Applied values get source:<tag>=website and check_date:<tag>. The changeset names the AI in ai_assisted and in the comment.

With your own API key

  1. Create an API key in the Claude Console, ideally one only for osmCorrection with a short lifetime (1 to 7 days).
  2. In step 1, tick Compare with AI under “Online checks”.
  3. Enter the key under AI assistance and choose the model. Without “Remember the key” it is forgotten when you close the tab.
  1. Download and check. Every object with a website whose opening hours have not been checked for a long time becomes a finding.
  2. At the finding, click Analyze website with AI. It usually takes 20 to 60 seconds and can be cancelled.
  1. Afterwards you see how many suggestions there are, which pages were read, what was rejected and what the analysis cost.
  1. With Enter the suggestions come as the next findings, each with quote and source. Compare the quote with the new value, then apply or skip.

If several objects have the same website (e.g. shop and building), it is analyzed and paid for only once.

With an AI agent (e.g. Claude Code)

An AI agent is a program on your computer that can run commands and write files, e.g. Claude Code, Kiro or Codex CLI. With Claude Code the analysis runs on your Claude plan instead of an API key.

  1. In step 1, choose the frame and click Create job for AI. The browser saves a job.md with all objects whose website can be analyzed. With many objects there are several files.
  1. For each file, create a new, empty folder and put the file into it.
  2. Start the agent in this folder, for Claude Code with claude in the terminal, and write: Work through job.md
  3. The agent fetches the objects from OpenStreetMap, saves the websites in the subfolder pages/ and writes one answer per website to answers/. If your usage limit is reached, simply start again later: finished answers are skipped.
  4. Back in osmCorrection, click Import the AI’s result … and choose the folder.
  5. Confirm or correct which AI wrote the answers. It asks for the maker of the model, not of the program: a Claude model in Kiro is Anthropic. This goes into ai_assisted in the changeset.
  1. osmCorrection takes the objects from the export (up to 24 hours later) or loads them fresh, checks the quotes against the saved pages and shows the suggestions for review as above. The import also works days later.

Safety: An AI agent can run commands on your computer. So use a separate, empty folder and allow each fetch one by one on the first run; then you see which addresses are fetched. The agent should only save pages and write answers. For fetching it uses a browser without a window and with an empty profile, or curl; nothing needs to be installed.

Frequently asked questions

Is anything changed in OpenStreetMap right away?

No. Applied values are only kept for later. Only “Upload” in step 3 writes them to OpenStreetMap. Exception: “Check on site …” creates the note right away.

I applied something by mistake.

Go back to the finding with Page ↑ and correct the value, or take the change out in step 3 with “remove”.

“No Overpass server answered”

The Overpass servers are sometimes busy. osmCorrection then loads the frame directly from openstreetmap.org. If that fails as well, wait a few minutes and load again.

No findings?

Then the chosen values in the frame are fine. Tick more checks or choose another area.
